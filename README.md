# SmartQueue — Digital Queue Management System

## Technology
- Frontend: React + Vite (Node.js/npm)
- Backend: Java 21 + Spring Boot 3 + Spring Data JPA
- Database: MySQL 8
- Communication: REST API

## Features
- Patient can request a digital token
- View today's queue and token statuses
- Receptionist can call the next waiting patient
- Receptionist can mark a token Completed or Skipped
- Estimated wait based on waiting patients × average consultation minutes

> This is a college-project demonstration. Receptionist access is not authenticated in this starter version. Do not use real patient data in production.

## Requirements
Install Node.js (LTS), Java 21, Maven (or use the included Maven wrapper generated by Spring Initializr), and MySQL 8.

## 1. Create the MySQL database
Run this in MySQL:
```sql
CREATE DATABASE smartqueue;
```

## 2. Start the backend
Open `backend/src/main/resources/application.properties` and set your MySQL username/password.
From the `backend` folder, run:
```bash
mvn spring-boot:run
```
Backend: http://localhost:8080

The backend creates the `queue_tokens` table automatically for development.

## 3. Start the frontend
From the `frontend` folder:
```bash
npm install
npm run dev
```
Open the URL Vite prints, normally http://localhost:5173.

## API endpoints
- `GET /api/tokens` — today's tokens
- `POST /api/tokens` — create a token; JSON: `{"patientName":"Asha","department":"General Medicine"}`
- `POST /api/tokens/call-next` — call the next Waiting token
- `PATCH /api/tokens/{id}/status` — set status; JSON: `{"status":"COMPLETED"}` or `{"status":"SKIPPED"}`
- `GET /api/health` — health check

## Notes
- Token sequence is generated for the current date and department.
- The queue list refreshes every 10 seconds.
- Estimated waiting time is an estimate, not a guarantee.
- For production, add authentication/authorization, validation, audit logs, privacy safeguards, migrations, and concurrency-safe token generation.
